# Patch 0089: build fix (typecheck found it)

Stacks on 0088. Not on your list; found while running `tsc` before starting the T6 and T8 work, and it stops the app bundling, so it goes first.

## What was wrong
- `src/screens/CashSheet.tsx`: since 0086, `CashSheet` took a prop called `plan` (the split-payment plan) **and** declared `const plan = useMemo(... planChange ...)` in its body. A parameter and a top-level `const` of the same name in one function is a JavaScript syntax error ("Identifier 'plan' has already been declared"), so Metro cannot bundle the app. `tsc` reports it as TS2300 twice and TS2339 once (`'kind' does not exist on type 'SplitPlan'`).
- `tests/changeimpact.test.ts` line 71: a list of drawers typed too narrowly for `Counts` (TS2322). The test itself runs fine; only `tsc` (which includes `tests/`) complained.

## Checklist

2. [x] `CashSheet`: the one place that used the prop (`livePlan`) now reads `splitPlan`. The local `plan` (the change plan) is untouched.
3. [x] `tests/changeimpact.test.ts`: the drawer list is cast `as Counts[]`.
4. [x] `tsc --noEmit` is clean (apart from the private Zeller package, which cannot be fetched in my sandbox; it is clean on your machine for that part as before).
