# Patch 0118: Sheets as first-class runtime nodes (the graph knows which window is open)

Stacks on 0117. Not a training course: this makes every window a place on the graph, so guidance never tells a person
to close the window they are already in, and never forgets one that is in the way. The living plan and log is
`docs/ROUTEGRAPH_GUIDANCE.md`.

## What you asked
> item 4 … the be-all-end-all (plumbing + the control-table move), then item 5-7 as allowed.

This is item 4 of the "Still to do" list, both halves: the plumbing that lets the graph know *which* window is open,
and the move of the control-to-screen table onto those window screens. (It is the first bullet that the 0117 plan
deferred with a written reason; that reason is now the capability that landed.)

## The problem
`stateNode` could only fold every sheet into the page under it. So a control that really lives on a sheet
(`bundle.continue` on `sheet_bundles`, `receipt.none` on `sheet_receipt`, `refund.go` on `sheet_refund`,
`customer.create` on `sheet_customer`, and 13 in all) had to be listed on the tab in `appControls.ts` on purpose.
Listing it on its sheet would have made the graph add a spurious "open the window" step while that window was already
open. That was hidden behind the plain answer, but it was wrong.

## How it works
- **A window can name itself.** `Sheet` (`src/ui/kit.tsx`) gained an optional `screen` prop, passed to `TrainingLayer`.
  `TrainingLayer` (`src/ui/TrainingLayer.tsx`) pushes that name as the layer's name when present, else an anonymous
  `useId`; the layer stack (`src/lib/trainingLayers.ts`) already reports the deepest layer through `topLayer()`.
- **The run reads the top layer.** `TrainSnap`/`snapOf` (`src/lib/trainingModule.ts`, `src/lib/trainingConds.ts`)
  gained `sheet`. `TrainingHost` sets it from `topLayer()` when that name is a known screen (`isKnownScreen`), else
  from the page that replaces one inline: the Return page names itself through `setRuntimeScreen` in
  `src/lib/trainingProbe.ts` (it is returned in place of Orders, not pushed, so it has no route of its own).
- **The engine uses it.** `stateNode` returns `snap.sheet` when the graph has that screen: after `locked` (the sign-in
  overlay is above the windows it opens), before `openLine`/route/tab. A fix inside the open window is no longer told
  to close it; one under it is still walked out through it (`forcedByWindow` now excepts the window the fix lives on).
- **Every sheet a control lives on names itself**, and `src/lib/appControls.ts` moved the whole contents of each onto
  that screen: cart menu, bundles, customer / new customer, price-adjust review, receipt, cash receive / change / give
  / return, order, the refund picker / done / Return page, and the practice pass and practice camera.
- **Shared, multi-home sheets stay anonymous on purpose.** The discount sheet and the line price / adjustment sub
  sheets are opened from more than one place and their controls are multi-home, so they fold into the page or tab they
  sit over; their controls keep pointing where the old words point.
