## How it works
- **Course `scanning`** (`src/training/modules/scanning.ts`, six minutes, routes include `pay`): Info (six steps), Show (seven steps), Guide (fifteen steps), Check 1 (three goals) and Check 2 (two goals).
- **A practice camera window.** A camera cannot scan an item that is not real, so in practice the Checkout camera button opens `PracticeScanSheet` (`src/ui/PracticeScan.tsx`) instead of the real camera. It follows the way the sign-in course draws a pass in place of the camera. It behaves like the real window: it stays open for any number of scans, shows a green message (`Added Bumble Bee`) or a red one (`Not found: <code>`) and closes with Done. It runs the same `onScan` Checkout uses for the real camera, so the till's own rules decide each message. `CameraScanner` chooses it only while training is running (`isTraining()`); the real camera is untouched.
- **The cards** (`src/lib/trainingScan.ts`): Bumble Bee, Red Dragon and Sticker Pack carry the practice item's SKU (the till matches a scan to a barcode, then to a SKU); the Torn label is a code nothing matches (it stands for a Keyring); the Gift card carries a real `shopify-giftcard-v1-` prefix. **There is no Keyring card and no cashier pass card on purpose:** the Keyring has to be added by hand for Check 2's torn-label goal to mean anything, and on Checkout a scanned pass signs that person in, which must never change who is signed in on the real till.
- **Spots.** `scan.camera` (the barcode button next to Search), and in the practice window `scan.done`, `scan.result` and `scan.card:<key>`. `Barcode128` gained an optional `label` for its accessibility text. A restarted practice run now also closes the camera window (`setCam(false)` in Checkout's reset).
- **What a step must allow.** A scan that finds an item adds it, so those Guide steps and goals say `allow: ['add']`; a scan that matches nothing adds nothing, so those say `allow: []` and any change is flagged as off course.
- **Check 2.** Goal 1 starts with a Red Dragon in the cart and asks for the Keyring (no card scans it, so the only way is the tile or Search). Goal 2 starts with a Bumble Bee in the cart and finishes when the Gift card window is open on the Payment page (`payOpen === 'gift'`), which is where the red gift card message sends the person. It is last because it leaves a window open.
- **Tests.** `tests/trainingscanning.test.ts` (7) runs the app's own `resolveScan`, `scanProblem`, `isBadgeCode`, `isGiftQr` and `findByBarcode` on every practice barcode, and checks that no card is a cashier pass, that nothing scans the Keyring, and that each Guide step and goal is finished by the right press or cart change.
- **Fixed on the way:** `tests/trainingbundlesdeals.test.ts` insisted its course was the last one registered, so adding a course broke it. It now checks the course is registered.

## Not covered
The Bluetooth scanner has no window and cannot be simulated, so it is taught in Info, Show and one Guide step, not practised. A cashier pass scanned by mistake is taught in Info and Show only (see above). Price check and Stock check use the same practice window if they are ever opened in practice, but this course does not teach them (that is `stock-lookup`, #17).
