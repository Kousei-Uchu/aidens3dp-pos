# Patch 0120: Training corrections part 1b, the window hand-off and the review note

Stacks on 0119 (soft locks and the cursor). Follow-up from the first device test of 0119 (T30).

## What you found on the iPad

1. **Discounts, Check 2, goal 2 of 3 still freezes touch** — nothing can be pressed, not even Exit.
2. **Change a price, Check 2, goal 1 of 3 does not work**, and its Guide step 25 ("Tap Charge") does
   not present the price review the second time around.
3. Your hunch: between some stages it does not reset the "order status" between the fake orders.

All three reproduced by reading the code and the tests; none reproduced on a device here (no iPad in
the sandbox).

## Causes found

### A. A window that closes is noted too late (fixes 1 and 2)

`Sheet` (in `src/ui/kit.tsx`) waits out `sheetGate` before it opens, and it said "a window has begun to
close" (`noteSheetHide`) from a `useEffect`. But a line window and its sub-window are **siblings in the
same render**: on a cart line, the line `Sheet` is `visible={!disc && !price && !adj}`, and the Discount
/ Item price / Line price `Sheet` sits next to it. When the sub-window closes, the line window opens in
the same render. React runs the two `useEffect`s in tree order, so the **opening** window's effect runs
**before** the closing window's effect has noted the hide. It therefore saw no close, waited no time,
and both windows changed in the same instant — the 0097 invisible-window soft lock, which is what
started the sheet gate in 0119.

- Discounts Check 2: goal 1 ends the moment Apply sets the line discount; Apply closes the Discount
  window and reopens the line window together. The touch-dead overlay lands right there, so goal 2 is
  unreachable.
- Change a price Check 2: Set price / Reset close the price window and reopen the line window the same
  way, so goal 1 stalls as soon as a price is set.

**Fix:** a closing window notes the hide **during the render**, not in the effect. Both windows still
render in one commit, but every effect runs after every render, so the opening window's effect always
sees the fresh hide and waits its 450 ms. (`src/ui/kit.tsx`.)

### B. The cart pane keeps "I have seen this review" across a practice run (fixes 3 and the step 25 part)

`CartPane` (and `GuidedCheckout`) hold `adjAck`, the fingerprint of the price-adjustment review the
person has already acknowledged. Charge shows the review once and again only when the adjustments
change. Checkout **stays mounted between a course's stages** ("tabs stay mounted: cart/scan state
survives navigation", `App.tsx`), and starting a stage called `resetCheckout()`, which back then only
reset Checkout's own screen state — never the cart pane's `adjAck`. So replaying the Guide left the
acknowledgement from the run before; the Guide's step 25 taps Charge, `needsAdjustReview` says the
person has already seen it, the review never opens, and the step cannot finish. This is your "it
forgets to reset the order status between the fake orders".

**Fix:** `trainingProbe` keeps a **set** of run-start resets, not one. `CartPane` and `GuidedCheckout`
each register one that clears the review acknowledgement (and any open window / stale cart line), so
`resetCheckout()` — called when a run starts and when a goal is started again — puts the checkout back
to how a practice run begins.
