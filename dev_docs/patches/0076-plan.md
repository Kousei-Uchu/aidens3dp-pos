# Patch 0076: going off course in the Guide (list of 5, point 1a)

Stacks on 0075.

## What you asked for
- Off-course handling (already in the Checks) should also apply to Guide.

## Cause
In the Guide the dimmed screen only lets taps through the ringed hole, so most strays were impossible. The rest (a window opened by the target, a swipe-back, an item removed in an earlier step, a stray discount from a Next-only step) were never compared against anything, because the baseline and `diagnose` only ran for Check goals.

## How it works
- Every Guide step now takes a baseline when it starts (the same `captureGoalStart` snapshot the Checks use) and runs `diagnose` each tick with its own rules.
- `Step` gains optional `allow`, `at` and `watch`, the same as a goal. `stepRules(step)` fills in `allow` when it is left out: a tap on a grid tile allows `add`, a tap on a cart line allows `remove`, anything else allows nothing.
- A step that waits on the till changing (`until: state`) must say `allow`; the checker refuses it otherwise.
- While a Guide step is off course: the card "Off course: ..." shows, the fix is ringed with the pointer, the dim lifts (the fix can be anywhere), Next-only blocking is dropped, Skip is hidden, and the bar offers **Start again**, which puts the till back exactly as the step began.
- With nothing to point at, no stale spotlight from the previous step is shown.

## Welcome course
- `g-tile`: no window, no other page. `g-charge`: a watch rule if the bee is taken out. `g-remove`: allows `remove`, on the cart.

## Tests
`tests/trainingcourse.test.ts` (+3): step rule defaults, the same stray kinds on a step, a step's own watch rule, validator.

## Known gaps (not yet covered by a rule)
- Locking the POS from the grid and a staff switch: not in the till snapshot, so not flagged by `diagnose`. Say if you want these added.
